# Research: wispr-flow
# Wispr Flow (macOS) — Full Teardown

## Company snapshot
- Wispr AI, founded 2021 (Tanay Kothari CEO, Sahaj Garg CTO); pivoted from neural wearable to Flow dictation software in 2024. Show HN launch Oct 2024 (https://news.ycombinator.com/item?id=41696153). Funding: $30M Series A (Menlo, 2025), $25M extension (Notable, Nov 2025), and $280M at $2B valuation (TechCrunch, Aug 17 2026). ~$3.8M revenue Jul'24–Jul'25, 40–50%+ MoM growth, ~80% 6-mo retention, ~19% paid conversion. Aug 5 2026: launched "Wispr Flow Notetaker" (Granola-style meeting notes from system audio, MCP integration with Claude/ChatGPT).

## Activation model
- Mac default push-to-talk: hold `fn` (falls back to `Ctrl+Opt` if no Apple fn key detected). Release = stop + insert. Explicitly NOT streaming: audio is captured while held, transcribed+formatted with full context after release, then pasted ("no real-time on-screen text during dictation" — full-context approach is what enables filler/self-correction cleanup).
- Hands-free (toggle) mode: `fn+Space`, OR double-tap the push-to-talk key mid-dictation to lock into hands-free, OR click the Flow Bar. Ends via same shortcut, stop (■) button, or Esc. 20-min session cap (warning at 19 min; was 5–6 min before Mar 2026). No silence-based auto-stop.
- Other defaults (Mac): Command Mode `fn+Ctrl` (or `Cmd+Ctrl+Opt`), Cancel `Esc`, Paste last transcript `Cmd+Ctrl+V`, Copy last transcript `Cmd+Ctrl+C`, Open Scratchpad `Opt+S`.
- Shortcut rules (docs.wisprflow.ai/articles/2612050838): max 3 keys; must include ≥1 modifier (fn counts) or mouse button 4–10 / middle-click (left/right click intentionally excluded; Magic Mouse/trackpad ineligible); no left+right same-modifier mixes; Caps Lock banned; no duplicates across actions; up to 4 shortcuts per action (Cancel: 1, and only Cancel may be bare Esc); core actions must keep ≥1 binding. Config: Settings → General → Shortcuts → Change; toast confirms capture; validates against OS-reserved combos (Cmd+C/V/X/Z/Tab/Space, screenshot keys, etc.). "Mouse Flow" (bind dictation to mouse button) shipped Mar 2026.

## On-screen UI (Flow Bar)
- Small pill "Flow Bar" at bottom-center of screen (notch-style bubble). Idle = compact bubble; recording = live waveform of "moving white bars" + Cancel (X) and Done/Stop buttons when expanded via click. Waveform is indicator-only (not clickable). Processing state between release and paste is brief (~sub-second typically).
- Draggable repositioning (Jul 2026): drop zones on bottom, left, right screen edges; docked vertically on side edges the waveform/controls reflow and menus open toward screen center.
- Right-click Flow Bar → Flow Menu: Hide for 1 hour, Settings, Microphone selection, Transcript history, Paste last transcript. Language picker lives directly in the Flow Bar (one click to switch).
- In hands-free, clicking bar center does NOT stop recording (must use stop/cancel/shortcut) — deliberate misclick protection.

## Text insertion mechanism (from forensic teardown, wensenwu.com/thoughts/wispr-flow-investigation)
- Architecture: Electron main app + native Swift helper binary; JSON-over-stdio IPC. Swift helper owns a system-wide active `CGEventTap` (intercepts EVERY keystroke pre-delivery; can suppress by returning NULL — this is how fn-hold is swallowed). GCD queues: `com.wispr-flow.keyboardService.keyEventQueue/runQueue/sendQueue`. Helper sends `KeypressEvent`, `AppInfoUpdate` (frontmost app changes), `AppContextHTML` (full AX tree traversals).
- Insertion methods (in order of preference): (1) direct text injection into focused element via Accessibility (AX) API; (2) clipboard paste simulation — copy formatted text, synthesize Cmd+V, then restore prior clipboard via `DelayedClipboardProvider` (does NOT preserve files/PDFs/RTFD/audio clipboard types); (3) synthetic key events (`SimulateKeyPress` IPC). Terminals: uses system paste shortcut; some terminals expecting Ctrl+Shift+V fail. Non-QWERTY layouts: refocus-recovery path wrongly assumes QWERTY paste key (documented bug).
- Fallbacks when no text field focused / paste fails: notification prompting manual paste via `Cmd+Ctrl+V`, or auto-popping the **Scratchpad** window showing the transcript with Copy button. Known failure class: apps intercepting synthetic events trigger wrong shortcuts; clipboard-race recovery could cancel an unrelated later dictation (documented).
- `EditedTextManager` v2 reads full textbox contents via AX after every dictation (observed up to 36,191 chars) and diffs user edits (`userEditMetaData`) — powers auto-dictionary learning and style adaptation.

## "Flow formatting" / auto-editing
- Smart Formatting (default ON everywhere; toggle only on iOS): context-aware capitalization (mid-sentence cursor = lowercase start), punctuation, spacing, auto-lists from numbered sequences, drops trailing period in messaging apps (WhatsApp/Slack/Discord/Teams) based on Writing Style setting; works in Chinese/Cantonese/Russian etc.
- Backtrack (self-correction): trigger words "actually", "scratch that", OR just restating the phrase — Flow removes the false start. Examples from docs: "Let's do coffee at 2 actually 3" → "Let's do coffee at 3"; "let's meet Tuesday, wait no, Friday" → "Let's meet Friday". Filler words (um, uh) stripped automatically. Third-party testing pegs backtrack/formatting at ~85–90% reliability.
- Auto Cleanup levels: None / Light / Medium / High (Style tab, added Apr 2026 v1.5.55).
- Spoken punctuation commands supported ("period", "full stop", "em dash", "degrees fahrenheit", "copyright symbol"...).
- "Press enter" spoken at end of dictation auto-submits in chat apps (desktop-only, case-insensitive, disabled in Command Mode). Per-app nudge targeting hardcoded for Slack, iMessage, Notes, Gmail, Claude, Superhuman.
- Original launch metric: 50–70% "zero-edit message rate" vs <5% for Apple/Google dictation; marketing claims "90% zero-edit."

## Context awareness / tone per app (docs.wisprflow.ai/articles/4678293671)
- Reads: active app bundle ID + URL, text near cursor (before/during/after), on-screen text via full AX-tree traversal (observed 214 elements, 9 levels deep, 336ms), conversation history, variable/file names in IDEs (Cursor/VS Code/Windsurf; requires Screen Reader Optimized mode; skips offscreen elements). Password fields never read. Historically also captured window screenshots to cloud (see Complaints).
- 4 app categories with per-category Style settings (configured during onboarding, editable in Style tab): Email (professional, proper-noun recognition of recipient names), Work messaging (Slack/Teams — casual business), Personal messaging (iMessage/WhatsApp/Telegram — informal), Other (neutral). Styles range "very casual → excited/formal". Switching Gmail→Slack auto-shifts tone. Notion: skips formatting when it detects placeholder hint text.
- Vibe-coding extras: "look at cron.py and vad.py" → "@cron.py and @vad.py" file tagging (Cursor/Windsurf chat panels only); long Claude Code prompts split into chunks; proper nouns pre-extracted via `/llm/extract_asr_words` LLM endpoint and fed to ASR as word-boost.
- Off switch: Settings → Data and Privacy → Context Awareness toggle; Enterprise admin can force-disable org-wide.

## Command Mode
- Hold `fn+Ctrl`, speak an instruction, release to execute — AI edits (e.g., "make this more concise", "make this more professional") applied to the just-dictated/selected text. Pro-plan feature ("AI Command Mode"). Mac+Windows only. Separate "Transforms" beta (May 2026): AI rewrites with custom prompts.

## Dictionary / snippets / replacements
- Dictionary sidebar tab: add/edit/delete words (30-char max in list UI; 1–60 chars per entry docs), no duplicates, one replacement rule per word. "Correct a misspelling" toggle maps wrong→right (applied post-transcription, e.g. Taney→Tanay). Entries do ASR "word boosting". Starring prioritizes words; usage-based ranking (Mar 2026). Bulk CSV import (desktop, ≤1,000 entries, 3MB). Team dictionaries on Business plan; personal beats team on conflict. Instant cross-device sync.
- Auto-learn: Settings → System → Extras → "Auto-add to dictionary" — monitors the pasted-into textbox for your edits; changed spellings auto-added, common words filtered, auto-entries marked with sparkle (✨) icon.
- Snippets: voice-triggered text blocks (trigger ≤60 chars, body ≤4,000 chars); rich text (bold/italic/links/lists) since v1.6.288 (Jul 2026). Text replacements for spoken shorthand → expansion (calendar links: say "c30" → calendly URL).

## Languages
- 104 languages; auto-detect across ~99, or restrict to selected set for accuracy (detection is per-session at start, not per-word). Language picker in Flow Bar. ~60% of dictations are non-English. Desktop app UI localized (EN/DE/ES/IT/PT, Jun 2026). Whispering explicitly supported (works "remarkably well"; third-party tests: 97%+ normal volume, 92–95% whispered).

## Hub app (notes/history window)
- Sidebar: Home (total words, shortcut reminder, stats card: streak/avg WPM/total words; full transcript history grouped by day, searchable; hover→copy/flag actions; history is local-per-device, no cross-device sync), Dictionary, Snippets, Style, Scratchpad (beta; cloud-synced voice notes, Recents, search, pin/edit/delete; floating notepad window, syncs Mac↔iPhone), Insights (Apr 2026: usage analytics, "communication profiles", team leaderboards), Settings/Help/Refer/Invite team.
- History retention: audio kept 14 days for retry-from-audio, then purged (transcript text remains). Esc-cancelled short recordings still saved to Recent activity.

## Sound design
- "Ping" on dictation start; distinct paste/completion sound on insert; sounds gated by Settings → System → Sound → Sound Effects toggle. Hands-free start = ping + white bars. "Mute music while dictating" option (OFF by default on Mac, ON Windows): mutes default output device during dictation, restores after; only if audio was already playing. No desktop haptics (haptics are iOS-keyboard-only).

## Onboarding + permissions (macOS, docs.wisprflow.ai/articles/3152211871)
- Sign in via browser (Google/Apple/Microsoft/SSO/email). Permission cards in-app: (1) Microphone → macOS dialog; (2) Accessibility → System Settings (required for context + insertion). Notetaker mode adds a system-audio capture step. Then: intro screens → "Tell us about yourself" (role questions feed Style defaults) → privacy notice → mic test with visual feedback → shortcut setup → language selection/auto-detect → interactive "Try it yourself" dictation demos → Flow Hub with welcome + stats. "Start at login" enabled (users complain it re-adds itself to Login Items).

## Failure handling
- Cloud-only; NO offline mode, no local fallback model (multi-day outages May–Jun 2026 = total dictation loss platform-wide). Requires internet; VPN/security tools can block ("Connection lost" doc).
- Failed transcription → "Failed to transcribe. Saved in the app." with Retry; retry-from-audio via Home history (Retry link next to recording duration; "Recover" for dismissed ones); needs ≥5s audio; impossible with Zero-Data-Retention mode (audio never saved). "No Model Available" and "Taking longer than usual" are documented error states. Uptime work Jul 2026: claimed 99.9% uptime + 30% latency cut.

## Pricing
- Free "Basic": 2,000 words/week desktop (1,000/wk iPhone). 14-day Pro trial, no card. Pro: $15/mo monthly or $144/yr ($12/mo). Students/educators: 3 months free then 50% off. Teams: $12/user/mo monthly, $10/user/mo annual, 3-seat minimum, team dictionary + leaderboard. Enterprise: custom — SSO/SAML, SOC 2 Type II + ISO 27001 claims, ENFORCED HIPAA (BAA locks Privacy Mode ON + Cloud Sync OFF), admin controls. No lifetime option; refunds post-trial only where legally required. 8,000-word first-week bonus for new desktop signups. HN launch promo was "HNLAUNCH" 33% off.

## Tech stack (confirmed)
- Client: Electron (main UI, cloud API, analytics) + Swift native helper (CGEventTap keyboard, AX API, CoreAudio); 6 binaries; hardened-runtime exceptions (`disable-library-validation`, `allow-unsigned-executable-memory`, `allow-dyld-environment-variables`, no app-sandbox, ATS disabled `NSAllowsArbitraryLoads`) — criticized as injection risk. Local store: SQLite `~/Library/Application Support/Wispr Flow/flow.sqlite` (observed 694MB/3,404 dictations incl. 198MB OPUS/WAV audio, transcripts raw/formatted/edited, AX context, metadata, tone-match pairs, screenshot BLOB column).
- Inference: Baseten dedicated GPU deployments on AWS us-east-1 (gRPC `model-v31pl413.grpc.api.baseten.co`, HTTP fallback chain endpoint). Custom ASR model (unnamed, unified single model since Jun 2026) + fine-tuned Meta Llama models for cleanup/formatting, optimized with TensorRT-LLM engine builder + Baseten Chains multi-step inference. Targets: p99 end-to-end <700ms; 100+ tokens in <250ms; Sahaj Garg: "we don't care at all about p50." Observed: 210ms model inference, ~416ms response stream. Subprocessors have included OpenAI, Anthropic, Cerebras. Backend: api.wisprflow.ai / api-east.wisprflow.ai / cloud.wisprflow.ai; Supabase auth. Analytics: PostHog (EU; feature flags: `mouse-flow`, `ax-context-v2`, `complex-textbox-extraction`), Sentry, Segment, Datadog — 1,183 distinct event types incl. per-keypress events; hourly `POST /history/upload` of metadata even with sharing disabled.

## Complaints (Reddit/HN/Trustpilot/reviews)
- Privacy (biggest): 2025 discovery that Flow uploaded active-window screenshots to cloud without disclosure; company initially BANNED the reporting user (CTO later apologized; Context Awareness redesigned). Apr 2026 HN front page: "Wispr Flow Is Tracking Every App/URL You Visit and Taking Screenshots" (news.ycombinator.com/item?id=47781148). Forensic report: every-keystroke interception; 1,688 app/URL events in 30h logged (x.com 133, github 47...); metadata uploads with Privacy Mode ON; training on data unless Privacy Mode enabled (off by default); two-toggle confusion (ZDR needs Privacy Mode ON + Cloud Sync OFF); Delve fake-SOC2 vendor scandal (Mar 2026, later clean A-LIGN SOC 2 Type I); CEO podcast showing per-user analytics of named employees; staffer LinkedIn post mining user dictations ("kindly" 5.6× in India) proving content retained/queryable.
- Reliability bugs: stuck-modifier CGEventTap bug suppressed 145 spacebar presses in 10 min (`removeStaleKeys` blind spot for key 61/Right Option); "Keyboard event buffer stalled"; wrong-window pastes when focus changes mid-dictation; QWERTY assumption breaks non-QWERTY layouts; synthetic-paste triggers rogue shortcuts in some apps; previous-clipboard pasted instead of dictation.
- Performance: Electron RAM hog (~800MB RAM / 8% CPU idle reported on Windows; fans on idle), freezes target apps (VS Code, Notepad++) mostly Windows; Mac "polished," Windows "afterthought."
- Latency creep: long-time payers report noticeably slower text rendering over time; suspicion that added cleanup features add latency; quality dips acknowledged (company shipped unified model + benchmarks Jun 2026 in response).
- Subscription fatigue: $144/yr min for a dictation utility; Trustpilot 2.7/5 vs G2 4.5/5 vs iOS App Store 4.8/5 (8,500+ ratings); recurring "works during trial, degrades after paying / works 60% of the time" pattern; referral-program gripes; app re-inserts itself into Login Items; browser extensions appear without clear consent; no offline = dead during outages.
- Feature gaps users cite: no Linux (FreeFlow open-source clone got Show HN traction: news.ycombinator.com/item?id=47411467); long dictations need chunking; history doesn't sync across devices.

## Praise (what feels magical)
- "Feels like magic" recurs: speak anywhere, polished text appears at cursor, no copy/paste, no app switching. Rahul Vohra (Superhuman): "the best AI product I've used since ChatGPT."
- Speed: users at 184 WPM vs 90 WPM typing (top-1% badge, gamified stats/streaks work); 3–3.5× faster than typing claims corroborated by reviewers; ~700ms cloud round-trip beats local Superwhisper large-v3 (1–2s+).
- Accuracy praised as "essentially perfect" for casual capture, even far-mic + music playing; whisper-quiet dictation works (office-safe); seamless mid-sentence code-switching between languages; names/jargon nailed via dictionary+context; filler/self-correction cleanup is the #1 cited differentiator vs Apple dictation/raw Whisper; tone matching per app "sounds like me."
- Cross-app universality (Chrome, Slack, terminals, IDEs) + vibe-coding integration (Cursor @file tagging) heavily praised by dev users.

## RECOMMENDATIONS
- Copy the winning interaction verbatim: hold-key push-to-talk with release-to-insert + double-tap-to-lock hands-free + Esc cancel; make the hold key configurable with fn/globe as default and validate against OS-reserved combos like Wispr does (max-3-key rule, mouse-button support is a loved power feature)
- Differentiate on privacy from day one — it is Wispr's biggest wound: open-source + local audio only, no screenshots/AX scraping by default, no per-keystroke telemetry, explicit single privacy toggle; publish a data-flow doc. Being 'the trustworthy Wispr Flow' is the clearest positioning available, especially since your app will be open-sourced
- Avoid Electron: user complaints about 800MB RAM and app freezes are constant; a native Swift/AppKit app with a small helper (or single process using CGEventTap only for the hotkey, not all keys — prefer NSEvent global monitor or MediaRemote/fn handling to passive taps) removes the 'keystroke interceptor' attack surface entirely
- Insertion: implement the same 3-tier ladder (AX direct set -> clipboard+Cmd+V with clipboard restore -> notification/scratchpad fallback), but fix Wispr's known bugs: preserve non-text clipboard types where possible, verify frontmost app hasn't changed before pasting (their #1 wrong-window complaint), and use layout-independent virtual keycodes for the paste synth (non-QWERTY bug)
- Latency budget: Wispr targets p99 <700ms end-to-end and users still complain about creep — design your REST API for streaming-partial ASR + fast final LLM pass, measure p90/p99 per user not p50, and consider showing live partial text (Wispr doesn't; instant feedback could be a visible differentiator)
- Ship the LLM cleanup layer, not just ASR: filler removal + Backtrack-style self-correction ('actually/scratch that/restatement') + per-app tone (4 categories: email/work-chat/personal-chat/other) is what users call magical; a raw transcript app loses to Wispr instantly
- Personal dictionary with ASR word-boost hints + auto-learning from user edits (diff pasted text after a few seconds) + misspelling replacement rules; mark auto-learned entries and let users star/delete — this loop is Wispr's stickiest retention feature
- Failure handling users will judge you on: always save audio locally and offer Retry from history; never lose words. Consider a small local fallback model for offline — Wispr's cloud-only outages are a top complaint and an easy win for you
- Sound design matters: distinct start-ping and completion/paste sounds, gated by one toggle, plus optional 'duck/mute media while dictating'; keep the recording HUD at bottom-center with a live waveform, click-to-stop protection in hands-free, and drag-to-dock edges
- Pricing pressure: Wispr's $144/yr causes churn to $8.49/mo Superwhisper and free/open tools; as an open-source Google-styled app, a generous free tier (or fully free) directly exploits their subscription fatigue
- Onboarding: mirror their flow (sign-in optional if possible -> mic permission -> accessibility permission with clear explainer -> shortcut choice -> interactive first-dictation tutorial) but keep 'tell us about yourself' optional; do NOT auto-add Login Item without consent (a repeated Wispr complaint)
- Support whispered speech and per-session language auto-detect with a quick language switcher in the HUD; 60% of Wispr dictations are non-English — multilingual quality is not optional
