# Research: reliability-formatting
# Reliability Engineering & Text Processing for macOS Dictation Apps — Research Report

## (a) NEVER-LOSE-WORDS ARCHITECTURE

### Crash-safe audio persistence
- **Format choice is the core decision.** CAF (Core Audio Format) is header-less-finalization: chunk sizes can be written as "unknown/growing," so a file interrupted by crash/kill remains playable. WAV/AIFF require the RIFF header sizes to be rewritten at the end of recording; a crash leaves a technically-invalid header (though raw PCM WAV is usually still recoverable by patching the header since data is contiguous PCM). M4A/AAC written via AVAudioFile is the worst: on crash the MOOV atom is missing and the file is unreadable (Apple dev forum thread 720691 "Write AAC files in a way that they are readable even in a crash").
- **Apple's official recommendation** (dev forum thread 766774, "Is there a recommended approach to safeguarding against audio recording losses via app crash?"): don't rely on `AVAudioRecorder`; use `AVAudioEngine`, install a tap on `inputNode` (`installTap(onBus:bufferSize:format:)`), and stream PCM buffers to disk incrementally with `AVAudioFile` (or lower-level Audio Toolbox). "If you are streaming PCM audio data to disk, you should be able to recover the recorded fragment after a crash." Apple's "Using Voice Processing" sample demonstrates the tap→AVAudioFile pattern. Related bug report: `AVAudioRecorder` loses audio recorded before an interruption (thread 781778).
- **Recommended pipeline**: AVAudioEngine inputNode tap → convert to 16 kHz mono PCM (via `AVAudioConverter`) → append to CAF (LPCM) via `AVAudioFile(forWriting:settings:)` per-buffer writes → fsync periodically. Recover-on-relaunch = scan recordings dir at startup for entries without a completed transcript and offer re-transcription.

### How competitors persist & recover
- **Superwhisper**: every dictation saved to `~/superwhisper/recordings/` (older installs `~/Documents/superwhisper/recordings/`; path customizable). Each recording is a Unix-timestamp-named folder (e.g. `1759009359/`) containing the audio file + `meta.json` with fields `result` (raw transcription), `llmResult` (AI-processed text), `rawResult`, `datetime`, `duration`, `processingTime`, `segments`. History tab: right-click any past recording → "Process Again" re-runs with current mode — explicitly marketed for "retry failed transcriptions... without re-recording" (superwhisper.com/docs/get-started/transcribe-history). No built-in bulk-delete/retention UI — docs literally tell users to set up a cron job to delete folders older than N hours (superwhisper.com/docs/get-started/history-management).
- **Wispr Flow** (cloud STT, no offline mode at all): on transcription failure shows error + **Retry button**; failed items retryable from History via inline "Retry" link next to recording duration; retry does not duplicate history entries. **If text insertion fails, the text is copied to clipboard and a "Paste" button appears** (graceful degradation from auto-insert → manual paste). Audio is stored locally "for a limited time," after which only transcript text is kept; if user/enterprise enables zero-data-retention (Settings → Data & Privacy), audio never saved and retry is impossible ("Retry failed. Audio file missing" / "Audio file not found" errors). "Taking longer than usual" state appears during Initializing/Stopping/Processing under server load/slow network/VPN; audio is "saved for retrying" during slow processing. Recording caps: 20-min max on Mac/Windows (warning at 19 min). Android has "automatic timeout recovery" if stuck in initializing/processing. A documented bug silently discarded valid dictation (empty/incomplete transcript, esp. quiet audio or numbers) — fix was app update + Retry from History (docs.wisprflow.ai article 6901148133). Trustpilot 2.7/5 with recurring complaints: quality drift over time, longer post-speech render waits, degradation after free trial.
- **VoiceInk** (open-source GPL-3.0 Swift, github.com/Beingpax/VoiceInk, ~4.3k stars): real-world failure mode documented in issue #687 — intermittent empty/truncated transcription because audio-hardware initialization completed ~1s AFTER recording stopped (race between hotkey press and AVAudioEngine start); lesson: pre-warm the audio engine on hotkey-down or keep it warm, and detect "0 buffers captured" as an error state.
- **Handy** (open-source Tauri/Rust, github.com/cjpais/Handy): pipeline = rdev hotkey → cpal capture at 16 kHz → Silero VAD via vad-rs (~1 ms/chunk) → whisper-rs (GGML) or Parakeet V3 int8 via transcribe-rs → optional LLM post-process → paste via enigo (xdotool/wtype on Linux).

### Network retry / timeout handling for cloud STT
- Deepgram streaming: server kills the WebSocket with close code 1011 + `NET-0001` if no audio received for ~10 s; official guidance = send text-frame `KeepAlive` message every 3–5 s; must send first audio within 10 s of open. Deepgram publishes a dedicated guide "Recovering From Connection Errors & Timeouts When Live Streaming" (developers.deepgram.com/docs/recovering-from-connection-errors-and-timeouts-when-live-streaming-audio).
- Pattern for our app: since raw audio is always on disk, the retry unit is the recording folder — enqueue failed uploads (persisted queue), exponential backoff, surface a per-item Retry in History, and never block a new dictation on a stuck old one. Wispr Flow additionally auto-retries once before surfacing the error.

### Clipboard preservation during paste-insert
- Standard insertion: write to `NSPasteboard.general`, post ⌘V via `CGEvent` (requires Accessibility permission), then restore prior pasteboard contents. **Superwhisper has an explicit "Restore clipboard" option that restores the previous clipboard value 3 seconds after the result is pasted** (changelog). Known failure mode: race conditions — openai/codex issue #11103 documents Superwhisper auto-paste racing with a TUI, pasting the wrong clipboard content.
- Mark transient writes with `org.nspasteboard.TransientType` (and `org.nspasteboard.AutoGeneratedType`) per nspasteboard.org conventions so clipboard managers ignore the temporary transcript write.
- Save/restore must capture ALL pasteboard types (use `NSPasteboard.pasteboardItems` snapshot), not just string, and use `changeCount` to detect if the user copied something new during the restore window.
- Alternative insertion path: Accessibility API `AXUIElementSetAttributeValue(element, kAXSelectedTextAttribute, text)` inserts at cursor without touching the clipboard; fails in non-AX apps (many Electron/Java apps, secure fields), so production apps combine: try AX insert → fall back to pasteboard+⌘V → fall back to "copied to clipboard, press Paste" (Wispr's final fallback). CGEvent keystroke-by-keystroke typing is a third fallback (slow, but no clipboard use).

## (b) FORMATTING PIPELINE

### Inverse text normalization (numbers, dates, currency, emails, URLs)
- **NVIDIA NeMo-text-processing** (github.com/NVIDIA/NeMo-text-processing) is the reference open-source WFST ITN library: `from nemo_text_processing.inverse_text_normalization.inverse_normalize import InverseNormalizer`; handles CARDINAL, DECIMAL, ORDINAL, DATE, TIME, MONEY, MEASURE, TELEPHONE, ELECTRONIC (emails/URLs), WHITELIST classes. Built on Pynini/OpenFst (Python — would need porting or sidecar for a Swift app; grammars can be exported as compiled FARs and run with OpenFst/Sparrowhawk in C++). Paper: arxiv.org/abs/2104.05055. WFSTs chosen because ITN has "extremely low tolerance to unrecoverable errors."
- **Model-native**: Whisper/Parakeet/Deepgram Nova-3/AssemblyAI Universal already emit written-form text (digits, punctuation) — modern approach is model-native ITN + light rule cleanup, not a full ITN pass. Deepgram exposes it as composable flags: `smart_format=true` (umbrella: punctuation+paragraphs+numerals+dates etc.), or granular `punctuate`, `paragraphs`, `numerals`, `filler_words`, `measurements`, `dictation`.
- If our custom REST API returns spoken-form text, budget for a client-side or server-side ITN stage; if it returns written form, only do app-side glue rules (spacing around punctuation, capitalization after insertion point, unit casing).

### Spoken commands
- **Deepgram `dictation=true`** (requires `punctuate=true`) converts spoken commands server-side: period→`.`, comma→`,`, colon→`:`, question mark→`?`, exclamation mark→`!`, new line→`\n`, new paragraph→`\n\n`. curl: `https://api.deepgram.com/v1/listen?dictation=true&punctuate=true` with `Authorization: Token KEY`, body `--data-binary @audio.wav`.
- **Apple macOS Dictation command vocabulary** (support.apple.com "Commands for dictating text on Mac" mh40695): "new line" (=Return), "new paragraph" (=Return×2), "period"/"full stop", "comma", "question mark", "exclamation mark", "open/close parenthesis", "quote"/"end quote", "hyphen", "dash", "ellipsis", "at sign", "ampersand", "caps on/off", "all caps", "numeral". Apple Silicon dictation now auto-inserts commas/periods/question marks so commands are optional.
- **"Scratch that"** (Dragon NaturallySpeaking): deletes the last utterance's text; repeatable up to 10 times. Implementation (patent US6125347): record per-utterance character counts; on "scratch that," emit that many deletions (or re-set the AX text value) and pop the utterance stack. Dragon also has "resume with <word>" for mid-utterance correction. Superwhisper Super Mode supports edit commands on selected text ("delete that," "capitalize that," "bold this," "select line above").
- Practical design: intercept command tokens in a post-STT rules layer keyed on exact phrases at utterance boundaries; keep an utterance-history stack with inserted-length metadata so "scratch that"/undo works even after insertion.

### Filler-word removal & self-correction rewriting
- Deepgram: strips "uh"/"um" by default; `filler_words=true` to keep them. AssemblyAI: disfluencies ("um," "uh," "hm") excluded by default; `disfluencies=true` to include (Universal-3 Pro strips ums/false starts/colloquialisms by default; re-enable via prompt).
- **Wispr Flow's marquee feature is LLM-based "auto-edits"**: filler removal + real-time backtracking — spoken "Let's meet at 2… actually 3" produces "Let's meet at 3" — plus auto-punctuation from pauses/tone, spoken-number→numbered-list formatting. Founders' claimed metric on HN (Show HN, news.ycombinator.com/item?id=41696153): "50–70% zero-edit messages vs <5% for competitors."
- **Superwhisper**: two-stage pipeline — STT model → optional LLM post-processing per "mode." Custom Modes carry user-written AI prompt, choice of STT model + LLM, auto-activation per app. Instructions empty by default; docs warn to tell the LLM the input is dictated speech.
- Whisper-specific hazard: hallucinations on silence/noise — most frequent fabrications "thank you" (24.76%), "thanks for watching" (10.32%) (arxiv 2501.11378). Mitigation: Silero VAD pre-filter (faster-whisper does this), trim long silences but preserve short pauses (Whisper uses pause structure for punctuation), beam_size=1, drop segments with no VAD-detected speech. Applies to any Whisper-family backend.

### Capitalization/punctuation restoration approaches
1. **Model-native** (preferred; Whisper, Deepgram Nova-3, AssemblyAI Universal, Parakeet-TDT all punctuate/capitalize).
2. **LLM post-pass** (Wispr/Superwhisper approach): most flexible, adds latency + rewrite-risk; OpenAI cookbook "Whisper_correct_misspelling" recommends GPT post-processing over prompt biasing for large vocab.
3. **Dedicated models/rule libs**: `deepmultilingualpunctuation` (pip; oliverguhr/fullstop-punctuation-multilang-large, EN/IT/FR/DE), `punctfix` (DA/DE/EN), `rpunct` (BERT), Silero te (punctuation+capitalization, 4 languages), NeMo punctuation_capitalization models. Microsoft's "Post-Stream Refinement" (Azure) is the two-tier pattern: fast partials, then retroactively replace segments with higher-quality reformatted text.

### Custom dictionary techniques
- **Model-level biasing (send with each request):**
  - Deepgram Nova-3/Flux: `keyterm` query param, repeatable (`&keyterm=a&keyterm=b`), multi-word via `+`/`%20`, max 500 tokens total across keyterms, no weights (weights silently treated as literals; commas/semicolons silently break boosting); claimed up to 90% keyword-recall improvement. Legacy `keywords=word:2` (with intensifier) for Nova-2.
  - AssemblyAI: `keyterms_prompt` — up to 1,000 phrases (≤6 words each) async, up to 100 terms ≤50 chars streaming; `word_boost` deprecated. Separate `custom_spelling` (from→to mapping applied post-transcription server-side).
  - Soniox: free-text `context` param up to 8,000 tokens (e.g. `{"context": "Celebrex, Zyrtec, Xanax..."}`) plus structured general context (domain/topic/names).
  - Google Cloud STT: `PhraseSet`/model adaptation with per-phrase `boost` values; docs warn high boost raises false positives ("fair" vs "fare" example). Whisper API: `prompt` param, only last 224 tokens honored, "not especially reliable."
  - **Design note for our custom REST API: reserve a `bias_phrases`/`context` field in v1 even if ignored initially.**
- **Post-hoc replacement (client-side):**
  - Exact/regex replacement lists (Wispr "replacement rules": correct spelling + "Correct a misspelling" toggle + the wrong form Flow produces; limit one rule per word).
  - Fuzzy/phonetic: Double Metaphone (primary+alternate 4-char codes; match if either code matches) to map misrecognized words to dictionary entries; combine with edit-distance threshold on the raw string to avoid overtriggering. JS lib: Talisman (yomguithereal.github.io/talisman/phonetics); research direction: LLM revision with phonetic-semantic context for named entities (arxiv 2506.10779).
- **Dictionary UI patterns (copy-worthy):** Wispr Flow: Dictionary tab; Add new; 1–60 chars; dedupe; star words for priority; sort (starred/newest/A–Z); search ⌘F; personal vs team tabs; CSV bulk import (≤1,000 entries, 3 MB); **auto-learn from user's typed corrections** (Settings → System → Extras; filters common words; ✨ sparkle icon marks auto-learned entries; instant effect, no restart; syncs across devices; personal overrides team). Snippets = voice-trigger → text expansion (say trigger phrase, inserts canned text). VoiceInk: "personal dictionary" + smart text replacements. Superwhisper: per-mode vocabulary via prompt/"use name spellings" context.

### Context-aware tone per target app
- Frontmost app detection: `NSWorkspace.shared.frontmostApplication.bundleIdentifier` (+ browser URL via AX/AppleScript for per-site rules).
- **Superwhisper context capture** (superwhisper.com/docs/common-issues/context): three context types — (1) selected/highlighted text in active window, (2) Application Context: app name, focused text-field contents, window title, system date/time/user, (3) Clipboard Context: text copied within ~3 s. Super Mode enables all three by default; Custom Modes opt in per type; modes auto-activate per app.
- **Wispr Flow "Styles"**: tone adaptation per app (formal in docs, casual in messengers, enthusiastic in email; English/desktop only); dev-mode: camelCase/snake_case syntax awareness, file tagging in Cursor/Windsurf, dev-jargon recognition (Supabase, Cloudflare, Vercel).
- **VoiceInk "Power Mode"**: per-app AND per-URL automatic profile switching (model, prompt, dictionary set).

## (c) LATENCY & PERCEIVED SPEED

- **Streaming partials**: Deepgram `interim_results=true` gives partials ~every second with first reads ~150 ms, `is_final=true` finalized segments; `endpointing` (default 10 ms silence) triggers `speech_final`; `utterance_end_ms` (≥1000, requires interim_results) fires `UtteranceEnd` on word-timing gaps; fastest finals ~200–300 ms with endpointing alone. AssemblyAI Universal-Streaming: **immutable transcripts** (never rewritten) at ~300 ms word emission; their benchmark: median 307 ms vs Deepgram Nova-3 516 ms; P99 1,012 ms vs 1,907 ms; $0.15/hr session-time billing. Google streaming: `is_final` + per-result `stability` score (UI advice: render only stability >0.8 as stable text), `single_utterance` auto-end.
- **Rendering pattern**: append `is_final` text to a committed buffer; render current partial as replace-whole-preview draft (appending a self-revising hypothesis causes "stuttering duplicates — a real UX bug"). Microsoft Azure "Post-Stream Refinement": keep low-latency partials, then retroactively replace segments with higher-accuracy reformatted text — the model for optimistic insertion + later correction. For system-wide insertion into other apps, retroactive correction is only safe via AX (replace a tracked range) — most shipping apps (Superwhisper/Wispr/VoiceInk) instead insert once at end; Wispr claims ~700 ms cloud round-trip; perceived speed comes from streaming the UI preview in the recording HUD, not from streaming insertion.
- **VAD auto-stop**: Silero VAD = de facto standard (512-sample windows @16 kHz, ~1 ms/chunk CPU; used by faster-whisper, Handy, LiveKit, Pipecat); tune confidence threshold + min-silence-duration (~500–1000 ms silence → stop). Also prevents Whisper silence-hallucination and saves API cost (only transcribe speech segments). WebRTC VAD is the lighter/less accurate alternative. Push-to-talk (hold-to-record) sidesteps endpointing entirely — Wispr/Superwhisper default to hold-hotkey (fn / right-⌘) with toggle-lock variant.
- **Cold-start**: VoiceInk issue #687 proves engine warm-up matters — start AVAudioEngine on hotkey-DOWN (or keep permanently warm) so first phonemes aren't lost; buffer from t=0 even before UI shows.

- Apple's recommended crash-safe pattern: AVAudioEngine inputNode installTap -> stream PCM buffers to disk incrementally via AVAudioFile (not AVAudioRecorder, which can lose pre-interruption audio, forum 781778)

- Wispr Flow on failure: auto-retry, then error with Retry button; retryable from History; if text insertion fails the text is copied to clipboard with a Paste button; audio kept locally only temporarily (zero-data-retention mode disables retry: 'Retry failed. Audio file missing')

- Superwhisper 'Restore clipboard' option restores previous clipboard value 3 seconds after paste; transient pasteboard writes should be marked org.nspasteboard.TransientType (nspasteboard.org); clipboard race documented in openai/codex issue #11103
- Text insertion fallback chain used in practice: AXUIElementSetAttributeValue(kAXSelectedTextAttribute) -> NSPasteboard + CGEvent Cmd-V -> 'copied to clipboard, press Paste' manual fallback
- Deepgram streaming closes WebSocket (1011, NET-0001) after ~10s without audio; official fix is text-frame KeepAlive every 3-5s; first audio must arrive within 10s
- Deepgram dictation=true&punctuate=true converts spoken commands server-side: period, comma, colon, question mark, exclamation mark, new line, new paragraph
- Deepgram keyterm (Nova-3/Flux): repeatable query param, max 500 tokens total, no weights, up to 90% keyword-recall improvement; AssemblyAI keyterms_prompt: 1,000 phrases async / 100 terms streaming, plus custom_spelling from->to mapping; Soniox context: free text up to 8,000 tokens; Google STT PhraseSet with per-phrase boost; Whisper prompt limited to last 224 tokens and unreliable
- NVIDIA NeMo-text-processing is the reference open-source WFST ITN library (InverseNormalizer class, Pynini/OpenFst, classes for DATE/MONEY/TIME/ELECTRONIC etc.); modern STT models emit written-form text natively so full ITN is only needed if the API returns spoken-form

- AssemblyAI Universal-Streaming emits immutable (never-rewritten) transcripts at ~300ms (median 307ms vs Deepgram Nova-3 516ms; P99 1,012ms vs 1,907ms); Deepgram interim_results partials ~150ms first read with is_final finalization; Google streaming exposes per-result stability (render >0.8 as stable)

- VoiceInk issue #687: intermittent empty transcriptions because audio hardware finished initializing ~1s after recording stopped — pre-warm/keep-warm the audio engine on hotkey-down; Handy pipeline: rdev hotkey -> cpal 16kHz -> Silero VAD (vad-rs, ~1ms/chunk) -> whisper-rs/Parakeet int8 -> paste via enigo

## RECOMMENDATIONS
- Record to CAF/LPCM via AVAudioEngine inputNode tap + AVAudioFile incremental writes (16kHz mono for API upload); never use AVAudioRecorder or M4A while recording; on relaunch, scan the recordings directory for entries lacking a completed transcript and offer one-click recovery
- Adopt Superwhisper's storage layout: one timestamped folder per dictation containing audio + meta.json (raw result, formatted result, duration, processing time, target app bundle ID); build History with per-item 'Process Again'/Retry; add the retention/auto-delete setting Superwhisper lacks (they tell users to write cron jobs)
- Treat the on-disk recording as the retry unit: persisted upload queue with exponential backoff, one silent auto-retry before surfacing an error, per-item Retry in History, and Wispr's insertion fallback ladder (AX insert -> clipboard+Cmd-V with snapshot/restore of all pasteboard types after ~3s using changeCount guard + org.nspasteboard.TransientType -> 'copied to clipboard' notification with Paste button)
- Pre-warm AVAudioEngine on hotkey-down (or keep warm) and buffer audio from t=0; VoiceInk #687 shows engine-start races silently eat the first second of speech; flag zero-buffer recordings as errors, never as empty transcripts
- Reserve bias/context fields in the custom REST API from v1: repeatable bias_phrases (Deepgram keyterm-style, ~500-token cap), optional free-text context (Soniox-style), and a custom_spelling map (AssemblyAI-style); client sends the user dictionary with every request
- Layer the formatting pipeline: model-native punctuation/ITN first; thin deterministic rules for spoken commands ('new line', 'new paragraph', 'period', 'scratch that' via utterance-length stack) so they work offline and instantly; optional LLM post-pass (per-app tone, self-correction rewriting) that can be toggled per mode and always preserves the raw transcript in history
- Copy Wispr's dictionary UX wholesale: instant-effect entries, starring, CSV import, one replacement rule per word, auto-learn from user's typed corrections (diff inserted text vs what user edited it to), sparkle badge for auto-learned words; add post-hoc Double Metaphone + edit-distance fuzzy replacement for dictionary terms the API misses
- Context-aware tone: key modes off NSWorkspace.frontmostApplication.bundleIdentifier (plus AX window title / browser URL), with per-app auto-activation like Superwhisper modes and VoiceInk Power Mode; capture focused-field text and selected text as LLM context, gated by a privacy toggle
- For perceived speed: stream partials into the recording HUD (replace-whole-preview rendering), insert finalized text once at the end (or AX-tracked-range correction later if we attempt optimistic insertion); use Silero VAD both for optional auto-stop (~700-1000ms silence) and to strip silence before upload (cost + Whisper-hallucination guard)
- Set explicit timeout policy: client-side request timeout with visible 'taking longer than usual' state (Wispr pattern), audio always preserved for retry, and a KeepAlive/heartbeat design if the custom API is streaming (Deepgram's 10s NET-0001 shows servers need one)
- Mine VoiceInk (Swift, GPL-3) and Handy (Rust) for implementation details before writing ours; note VoiceInk's GPL license means read-for-ideas, not copy, if we want a permissive license for our open-source release

## OPEN QUESTIONS
- Will our custom REST API return written-form (ITN'd, punctuated) text or raw spoken-form? Determines whether we need a client/server ITN stage (NeMo-style WFST) or only light glue rules
- Will the API support streaming (WebSocket/SSE partials) or only batch REST? Batch-only caps perceived latency at upload+inference time and rules out live preview text
- What are the API's auth, max-audio-length, and timeout semantics — do we need chunked upload for 20-min recordings and KeepAlive for long sessions?
- Target license for open-sourcing (GPL-contamination question re: VoiceInk patterns; whisper.cpp is MIT, FluidAudio/Parakeet weights have their own terms)
- Do we want optimistic insertion into third-party apps (AX range tracking is fragile across Electron/secure fields) or HUD-preview + single final insert like all shipping competitors?
- Exact latency budget: Wispr's ~700ms cloud round-trip is the bar; what does our API deliver end-to-end for a 10s utterance?
- How much LLM post-processing runs server-side vs on-device (Apple Foundation Models / MLX small model) for the tone/self-correction pass, and what is the offline story overall?
