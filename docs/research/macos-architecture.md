# Technical research: macOS system-wide dictation utility (native Swift vs Electron)

## (a) Global hotkeys and fn/Globe key capture

**Three API tiers:**
1. `RegisterEventHotKey` (Carbon, still fully supported): combo hotkeys only (key + modifiers). Sandbox/MAS-safe, no TCC permission needed. Cannot register a bare modifier (fn/Cmd/Opt alone). This is what `sindresorhus/KeyboardShortcuts` uses under the hood (https://github.com/sindresorhus/KeyboardShortcuts — fully sandbox/MAS compatible, `KeyboardShortcuts.Recorder` SwiftUI view for user-customizable shortcuts, `KeyboardShortcuts.Name` registration, `.onKeyDown`/`.onKeyUp` handlers — the onKeyUp is what you need for push-to-talk release with combo hotkeys).
2. `NSEvent.addGlobalMonitorForEvents(matching: .flagsChanged)`: listen-only (cannot consume events). Detect fn via `event.modifierFlags.intersection(.deviceIndependentFlagsMask).contains(.function)`, keyCode 63. Requires Accessibility or Input Monitoring trust for global monitoring of keyDown; flagsChanged monitoring also gated.
3. `CGEventTap` (`CGEvent.tapCreate`, mask `CGEventMaskBit(kCGEventFlagsChanged)`): the only way to both detect AND consume the fn key. Setup: `CGEventTapCreate(kCGSessionEventTap, kCGHeadInsertEventTap, options, mask, callback, userInfo)` → `CFMachPortCreateRunLoopSource` → add to run loop (dedicated thread recommended). Read `kCGKeyboardEventKeycode` field to distinguish keys: fn=63, L/R Option=58/61, L/R Command=55/54, L/R Control=59/62, L/R Shift=56/60. Return NULL from callback to consume; return event to pass through. Fire callbacks only on state transitions (track pressed state per key) since flagsChanged fires for every modifier change.

**Permissions for taps:** `.listenOnly` tap → Input Monitoring TCC (`kTCCServiceListenEvent`; check `CGPreflightListenEventAccess()`, request `CGRequestListenEventAccess()`). `.defaultTap` (consuming) → Accessibility (`kTCCServiceAccessibility` / `AXIsProcessTrustedWithOptions`). Apple DTS confirms `kTCCServiceAccessibility`, `kTCCServicePostEvent`, `kTCCServiceListenEvent` are three independent TCC buckets; Accessibility grant implies Input Monitoring in practice (no second prompt). `CGEventTapCreate` returns NULL when permission missing — use that as the trigger to show a permission banner.

**fn-key gotchas (from 10xChengTu/input0 docs/feature-single-key-hotkey.md — the best public writeup):**
- The fn key's system short-press behavior (emoji picker / input-source switch / start Dictation) is processed at the IOHID layer and CANNOT be blocked by CGEventTap. Workaround every shipping app uses: read `defaults read com.apple.HIToolbox AppleFnUsageType`; if != 0, prompt the user to set System Settings → Keyboard → "Press 🌐 key to" → "Do Nothing" (VoiceInk/Wispr-class apps show a banner for this).
- Consuming fn also silences fn+F-key media behavior while held; consuming Cmd-as-PTT breaks Cmd+C/V in other apps (avoid offering bare Cmd).
- Karabiner-Elements is the #1 conflicting app (its virtual HID driver grabs fn); BetterTouchTool and Rectangle Pro also conflict.
- Wispr Flow fallback behavior: if a non-Apple external keyboard was connected at first run, it can't detect fn and falls back to Ctrl+Opt as default PTT.
- Event taps get silently disabled: handle `kCGEventTapDisabledByTimeout` and `kCGEventTapDisabledByUserInput` in the callback by calling `CGEvent.tapEnable(tap:enable:true)`; run a periodic (~5s) health check on `CGEvent.tapIsEnabled()`; "a non-nil tap is not a healthy tap" (danielraffel.me TIL 2026-02-19). Re-signing the binary creates a new TCC identity — dev builds silently lose grants.

**Hold-vs-toggle detection (proven patterns):**
- Wispr Flow: hold fn = push-to-talk (transcribe+paste on release); double-tap fn (or fn+Space) = hands-free lock; double-tap while holding locks the session.
- Hex (kitlangton/Hex, `HotKeyProcessor.swift`): modifier-only hotkeys use a 0.3s threshold to distinguish accidental chord use from intentional PTT; regular hotkeys use configurable `minimumKeyTime` default 0.2s; press shorter than threshold = toggle-lock, longer = hold mode; ESC cancels; mouse clicks/extra modifiers within threshold abort the trigger.
- VoiceInk: three modes — hybrid (brief press toggles, long press = PTT), pure push-to-talk, pure toggle; dual hotkey slots.

## (b) Mic capture with AVAudioEngine

- `AVAudioEngine.inputNode.installTap(onBus: 0, bufferSize: 1024–4096, format: inputNode.outputFormat(forBus: 0))`. You CANNOT request 16kHz directly on the tap (mic renders at hardware rate, typically 44.1/48kHz Float32). Convert with `AVAudioConverter` from input format to `AVAudioFormat(commonFormat: .pcmFormatInt16 (or Float32 for whisper.cpp), sampleRate: 16000, channels: 1, interleaved: false)` using `convert(to:error:withInputFrom:)` + `AVAudioConverterInputBlock`; allocate output `AVAudioPCMBuffer` with ~2x expected frameCapacity. Known-good reference: whisper.cpp issue #2008 and TensorFlow speech_commands AudioInputManager.swift.
- **Device changes / AirPods:** macOS has no AVAudioSession. Observe `NSNotification.Name.AVAudioEngineConfigurationChange` — the engine stops itself on route/format change; the only reliable recovery on macOS is to tear down and recreate the whole engine (AudioKit issue #2130; supermegaultragroovy.com AirPods post). AirPods expose two separate CoreAudio devices on macOS: 2-ch output-only (A2DP) and 1-ch input-only (HFP); recording from them forces the low-quality HFP switch (~0.5–2s of lost/garbled audio at start — Wispr Flow has a help article on missing first words). To choose a specific input device rather than system default, set the device on the inputNode's audio unit via `kAudioOutputUnitProperty_CurrentDevice` (AudioObjectID from `AudioObjectGetPropertyData` with `kAudioHardwarePropertyDefaultInputDevice`), or use AudioObjectAddPropertyListenerBlock on default-input to detect switches.
- **Voice processing / AEC:** `try inputNode.setVoiceProcessingEnabled(true)` (macOS 10.15+, wraps AUVoiceProcessingIO): gives echo cancellation so speaker audio isn't transcribed. Caveats: silently changes tap format channel count (reported 5–9 channels — handle format dynamically); reduces input gain noticeably; enabling on input auto-enables on output node; fails with aggregate-device channel-count mismatch when input and output devices differ (Apple forums thread 810129); adds system "mic mode" UI. Most dictation apps skip AEC and instead optionally mute output: Wispr Flow "Mute music while dictating" mutes default output device during dictation and restores after (off by default on Mac, on by default on Windows).
- 16kHz mono Float32 is what whisper.cpp wants; 16kHz Int16 is typical for REST STT APIs. Buffer/stream via chunked upload or WebSocket depending on the custom API.

## (c) Inserting text into the frontmost app — three methods, all needed

1. **Pasteboard + synthesized Cmd-V** (primary method used by VoiceInk/Hex/Handy/Wispr): save `NSPasteboard.general` contents (changeCount + items), write transcript, post Cmd-V via `CGEvent(keyboardEventSource:virtualKey:9 (v),keyDown:)` with `.maskCommand` flag posted to `.cghidEventTap` (or `.cgSessionEventTap`), then restore old pasteboard after ~100–300ms delay. Works in virtually every app incl. terminals, browsers, Electron, Java apps. Mark the write with `org.nspasteboard.TransientType` (+ `org.nspasteboard.AutoGeneratedType`) so clipboard managers (Maccy et al.) skip it; `org.nspasteboard.ConcealedType` is the password convention (see nspasteboard.org). Downsides: clobbers user clipboard briefly (restore race with clipboard managers), Cmd-V can be remapped, paste sounds/undo semantics.
2. **CGEvent unicode typing:** `CGEvent(keyboardEventSource:virtualKey:0,keyDown:true)` + `keyboardSetUnicodeString(stringLength:unicodeString:)` — undocumented 20-UTF16-char truncation limit; chunk into ≤20-char pieces with ~4ms delays (enigo-rs does exactly this, see enigo issue #68). Looks like real typing (works where paste is blocked, e.g. some IDE vim modes), but slow for long transcripts, can interleave with real user keystrokes, and layout-independent only via the unicode-string trick. Requires Accessibility/PostEvent TCC.
3. **Accessibility AX API:** get `AXUIElementCreateSystemWide()` → `kAXFocusedUIElementAttribute` → `AXUIElementSetAttributeValue(el, kAXSelectedTextAttribute, text)`. Cleanest (no clipboard, instant, can also READ context around cursor — needed for Wispr-style context awareness and cursor-position insertion). Reliability by app type: native AppKit apps = excellent; Chromium browsers = OK once the a11y tree is on; Electron apps = flaky (returns success without inserting; Electron issue #36337 selection bugs; must first set `AXManualAccessibility` = true on the app element to force Chromium to build the a11y tree — `AXEnhancedUserInterface` is VoiceOver-reserved and causes window-move side effects; Electron issue #37465 reports even AXManualAccessibility failing with kAXErrorAttributeUnsupported in some versions); terminals = poor (no editable AX text element; use paste — Terminal/iTerm2 handle bracketed paste well); Google Docs/canvas web apps = AX insertion invisible to JS, must paste. Practical shipped strategy: per-app allow/deny list → try AX, fall back to paste, offer "type it" mode as user setting. Note App Store guideline 2.4.5 rejections for CGEvent.post-based paste (dev forums thread 820594) — another reason to distribute outside MAS.
- **Secure input:** when any app enables secure input (`EnableSecureEventInput`, auto-enabled by `NSSecureTextField`, Terminal's "Secure Keyboard Entry", password fields, lock screen), event taps stop receiving keystrokes (hotkeys die) though audio + paste still work. Detect via `IsSecureEventInputEnabled()` (Carbon, TN2150); find culprit by walking processes for `kCGSSessionSecureInputPID` or `ioreg -l -w0 | grep SecureInput`. Wispr Flow's help flow: symptom = "hold-to-talk keeps working while shortcuts are blocked"; fixes = unfocus password field, Terminal → uncheck Secure Keyboard Entry, quit offender, lock/unlock screen, re-login; UX copy admits "macOS does not always accurately identify which app is holding Secure Event Input." Best practice: watch IsSecureEventInputEnabled on a timer, show a HUD state ("secure field — dictation limited") and skip hotkey-based features gracefully; never try to bypass.

## (d) Permissions & TCC UX

- Needed: **Microphone** (`NSMicrophoneUsageDescription` in Info.plist; `AVCaptureDevice.requestAccess(for:.audio)` — prompt appears on first mic use), **Accessibility** (`AXIsProcessTrustedWithOptions([kAXTrustedCheckOptionPrompt: true])` — shows system dialog linking to Settings; needed for consuming event tap + CGEventPost + AX insertion), **Input Monitoring** (`IOHIDCheckAccess(kIOHIDRequestTypeListenEvent)` / `CGPreflightListenEventAccess` + `CGRequestListenEventAccess`) — often unnecessary if you have Accessibility. There is NO API to programmatically grant; user must toggle in System Settings → Privacy & Security.
- Deep links: `x-apple.systempreferences:com.apple.preference.security?Privacy_Accessibility`, `?Privacy_Microphone`, `?Privacy_ListenEvent`.
- Onboarding pattern used by VoiceInk/Wispr/Hex: dedicated setup screen with per-permission cards (status dot, "Grant" button opening the exact Settings pane, live polling every 1–2s to flip the checkmark; AXIsProcessTrusted can return stale values right after toggling on Ventura+ — poll, and warn the user a relaunch may be needed). Dev/debug: `sudo tccutil reset Accessibility com.your.bundleid` (and `reset All`). Critical: TCC keys off code-signing identity + path — every re-sign or moved binary re-prompts; ship signed, stable-path builds even in beta. MacPaw/PermissionsKit is a maintained wrapper (SPM, sandboxed-compatible) covering mic/accessibility/full-disk; jano.dev 2025 Accessibility-Permission post is a good implementation reference.
- launch-at-login: `SMAppService.mainApp.register()` (macOS 13+), or sindresorhus/LaunchAtLogin-Modern.

## (e) HUD overlay + menu bar

- **Overlay:** subclass `NSPanel` with `styleMask: [.nonactivatingPanel, .borderless (or .titled+.fullSizeContentView)]`, `isFloatingPanel = true`, `level = .floating` (use `.screenSaver` (=1000) or `.statusBar` to float over full-screen video), `collectionBehavior = [.canJoinAllSpaces, .fullScreenAuxiliary]`, `backgroundColor = .clear`, `isOpaque = false`, `hasShadow` as desired, `ignoresMouseEvents = true` for pure click-through HUD (or `becomesKeyOnlyIfNeeded = true` if it has buttons), `hidesOnDeactivate = false`, override `canBecomeKey`/`canBecomeMain` (false for pure HUD). Host SwiftUI via `NSHostingView(rootView: MyHUD().ignoresSafeArea())`. Never use SwiftUI `Window`/`WindowGroup` for this — they activate the app and steal focus. References: cindori.com/developer/floating-panel (canonical FloatingPanel<Content: View> pattern), fazm.ai/blog/swiftui-floating-panel, markusbodner.com Spotlight-like panel. Position with `NSScreen.main.visibleFrame` (Wispr-style bottom-center pill).
- **Menu bar:** SwiftUI `MenuBarExtra` (macOS 13+) is still limited in 2025/Xcode 26: no 1st-party API to open/close programmatically, no NSStatusItem access, `SettingsLink` broken from menu bar context (see steipete.me "Showing Settings from macOS Menu Bar Items"), `.window` style lacks fade-out/animation control. Workarounds: orchetect/MenuBarExtraAccess (binding-controlled presentation + underlying NSStatusItem), lfroms/fluid-menu-bar-extra. For an animated recording state icon (waveform in the status item), plain `NSStatusItem` + `NSStatusItem.button` with custom view/animated template image is the pro choice (multi.app "Pushing the limits of NSStatusItem"). Use `LSUIElement`/`Info.plist "Application is agent" = YES` + `NSApp.setActivationPolicy(.accessory)` so no Dock icon.

## (f) Sounds

- macOS has no AVAudioSession/ducking problem: `AVAudioPlayer` or `NSSound` plays mixed over other audio by default — nothing pauses Spotify. Keep player instances retained (sound stops if deallocated). For sub-10ms latency start/stop cues, pre-load `AVAudioPlayer.prepareToPlay()` or use `AVAudioEngine`+`AVAudioPlayerNode` on the same engine, or `AudioServicesCreateSystemSoundID` for fire-and-forget.
- Respect System Settings → Sound → "Play user interface sound effects": route through AudioToolbox and mark with `AudioServicesSetProperty(kAudioServicesPropertyIsUISound, ...)= 1` (Eternal Storms tip) — NSSound ignores this setting. UI sounds also follow the separate "alert volume" and selected alert output device.
- Optional Wispr-style "mute music while dictating": set default output device volume to 0 (CoreAudio `kAudioDevicePropertyVolumeScalar` / `kAudioHardwareServiceDeviceProperty_VirtualMainVolume`) or send media-pause key event; restore on stop. Hex ships start/stop/cancel sounds as bundled resources triggered from its TCA effects (`SoundEffect.swift`, Resources/Audio/).

## (g) Distribution outside the App Store

- MAS is a non-starter: App Sandbox forbids CGEventTap consumption, CGEventPost paste (guideline 2.4.5 rejections), fn interception, and Sparkle; Accessibility-dependent apps generally can't ship on MAS. Wispr Flow, Superwhisper (direct build), VoiceInk all ship Developer ID.
- Pipeline: Apple Developer Program ($99/yr) → Developer ID Application cert → enable Hardened Runtime (required for notarization; add entitlements `com.apple.security.device.audio-input`, and if you load whisper.cpp-style JIT nothing extra needed; avoid `--deep` signing) → `xcrun notarytool submit app.zip --keychain-profile X --wait` (App Store Connect API key auth) → `xcrun stapler staple` → verify `spctl -a -t exec -vv`. Notarize a ZIP; distribute DMG or ZIP (staple the .app inside; if DMG, staple the DMG too).
- **Sparkle 2** (sparkle-project/Sparkle): `SPUStandardUpdaterController`, `SUFeedURL` + `SUPublicEDKey` (EdDSA, `generate_keys`), appcast.xml hosted anywhere (GitHub raw/releases works), `generate_appcast` tool signs archives. Sparkle compares `CFBundleVersion` (build number), not the marketing version — always bump it. Non-sandboxed setup is simple; if you ever sandbox: XPC services must keep `-spks`/`-spki` bundle-ID suffixes + mach-lookup temporary exceptions, and sign components individually in order (XPC services → framework → app) (steipete.me "Code Signing and Notarization: Sparkle and Tears"). Since the app is going open source: GitHub Releases + appcast via CI (VoiceInk has release automation scripts to copy).

## (h) Swift/SwiftUI vs Electron — verdict for THIS app: native Swift, unambiguously

Electron hard blockers/penalties for this exact feature set:
- `globalShortcut` cannot register fn or bare modifiers (electron issue #16714 open since 2019); media keys flaky (#20788); non-QWERTY layout bug (#1099). Workaround = uiohook-napi/native N-API module — at which point you're writing the native code anyway, in a worse debugging environment (uiohook can't consume fn either without a custom CGEventTap module).
- No AX text insertion, IsSecureEventInputEnabled, CoreAudio device control, or CGEventTap without custom native modules; every one is a node-gyp/notarization liability.
- Non-activating overlay: `NSWindow` "does not support nonactivating panel styleMask" (electron issue #35815); panel support PR #34388 was a runtime hack; community relies on fragile `electron-overlay-window`/`@akiflow/electron-panel-window` native patches; focus-stealing on show is a chronic complaint.
- Footprint: Wispr Flow (Electron) measured at ~800MB RAM and ~8% CPU while idle on an M1 Pro MBP, fans spinning, "freezes apps" complaints on r/macapps — the single most-cited reason users switch to Superwhisper/VoiceInk (native ~60–150MB, ~0% idle). An always-resident push-to-talk utility lives or dies on idle cost.
- Startup latency to first audio frame, and bundle size (~250MB vs ~15–30MB native + model).
- Electron's only real advantages (cross-platform, web UI velocity) are irrelevant for a Mac-only, Google-styled, open-source app; Tauri (used by Handy) fixes RAM but still needs the same native Swift/ObjC/Rust interop for fn, AX insertion, and NSPanel.

SwiftUI vs AppKit split for the animated HUD: use SwiftUI for settings/onboarding/menus (MenuBarExtra or NSStatusItem + NSHostingView) and for HUD content, but host the HUD inside an AppKit NSPanel (see (e)). For a 120Hz waveform: SwiftUI `TimelineView(.animation)` + `Canvas` is fine for a small pill-sized view; if profiling shows dropped frames, drop to CALayer/CADisplayLink (AppKit-managed display links track per-display refresh incl. ProMotion) or a tiny Metal layer. Material-3-style springs map well to SwiftUI `.spring(response:dampingFraction:)`/PhaseAnimator; keep the HUD view hierarchy shallow (SwiftUI diffing cost grows with depth — 8.3ms/frame budget at 120Hz, realistically ~5ms).

## Misc landmines
- macOS Tahoe (26.x): WindowServer gate `CGXSenderCanSynthesizeEvents()` drops some synthesized events from unsigned/daemon contexts ("Dropping mouse down event because sender's PID isn't 0 or self"); `AXIsProcessTrusted` doesn't reflect PostEvent — check `CGPreflightPostEventAccess()`. Properly signed foreground apps with Accessibility grants are fine, but test paste-injection on Tahoe early. (nick-liu.com/posts/tahoe-hotkey-dead-end)
- Wispr Flow exposes URL schemes (`wispr-flow://start-hands-free`) — a nice pattern for Raycast/Shortcuts integration; ship `yourapp://toggle`, `yourapp://start`, `yourapp://stop`.
- Missing-first-words: start the AVAudioEngine (or keep it warm/prewarmed) on keyDown immediately, before UI; AirPods HFP switch loses ~0.5–2s — consider buffering from tap install and/or showing "mic warming" state; Wispr has a dedicated help article on this complaint.
- VoiceInk issue #687: intermittent empty/truncated transcription after hotkey trigger — race between engine start and capture; design the recorder as a state machine with explicit `warming → recording → finalizing` states.

## KEY FACTS
- fn/Globe key can only be detected+consumed via CGEventTap on kCGEventFlagsChanged (keyCode 63); RegisterEventHotKey and Electron globalShortcut cannot register bare modifiers (electron/electron#16714)
- The fn key's system action (emoji picker/Dictation) is handled at IOHID layer and cannot be blocked by CGEventTap — apps must check `defaults read com.apple.HIToolbox AppleFnUsageType` and prompt user to set 'Press 🌐 key to' = 'Do Nothing'
- TCC has three independent buckets: kTCCServiceAccessibility, kTCCServicePostEvent, kTCCServiceListenEvent; .listenOnly tap needs Input Monitoring (CGPreflightListenEventAccess/CGRequestListenEventAccess), consuming .defaultTap needs Accessibility (AXIsProcessTrustedWithOptions); Accessibility grant implies Input Monitoring
- Event taps get silently disabled — must handle kCGEventTapDisabledByTimeout/kCGEventTapDisabledByUserInput by re-calling CGEvent.tapEnable and run periodic tapIsEnabled health checks; re-signing the binary invalidates TCC grants
- AVAudioEngine inputNode cannot tap at 16kHz directly; tap at hardware format and convert with AVAudioConverter to 16kHz mono (Int16 for REST APIs, Float32 for whisper.cpp)
- On macOS the only reliable recovery from AVAudioEngineConfigurationChange (AirPods/device switch) is to discard and rebuild the whole engine; AirPods expose separate A2DP-output and HFP-input CoreAudio devices and lose ~0.5–2s at record start
- inputNode.setVoiceProcessingEnabled(true) gives echo cancellation but silently changes channel count (5–9ch), reduces gain, and fails on mismatched input/output devices; shipping apps instead offer 'mute music while dictating' (Wispr Flow: mutes default output device, off by default on Mac)
- Text insertion: pasteboard+synthesized Cmd-V (virtualKey 9 + maskCommand, save/restore clipboard, mark org.nspasteboard.TransientType) is the universal method; AXUIElementSetAttributeValue(kAXSelectedTextAttribute) is cleanest but silently fails in Electron apps and needs AXManualAccessibility=true to wake Chromium's a11y tree; CGEventKeyboardSetUnicodeString truncates at 20 UTF-16 chars (chunk with ~4ms delays, as enigo does)
- Secure input (IsSecureEventInputEnabled, TN2150) blocks all event taps/hotkeys while active (password fields, Terminal Secure Keyboard Entry); paste and audio still work — Wispr Flow documents 'hold-to-talk keeps working while shortcuts are blocked' as the diagnostic
- Hold-vs-toggle: Hex uses 0.3s threshold for modifier-only hotkeys (0.2s minimumKeyTime for combos), press<threshold = toggle-lock, ESC cancels; Wispr Flow: hold fn = PTT, double-tap = hands-free lock; VoiceInk offers hybrid/PTT/toggle modes
- HUD overlay: NSPanel with .nonactivatingPanel, isFloatingPanel=true, level=.floating/.screenSaver, collectionBehavior [.canJoinAllSpaces,.fullScreenAuxiliary], ignoresMouseEvents for click-through, SwiftUI content via NSHostingView (cindori.com/developer/floating-panel canonical pattern); SwiftUI Window types steal focus and cannot do this
- MenuBarExtra (SwiftUI) still lacks programmatic open/close, NSStatusItem access, and working SettingsLink as of Xcode 26 — use NSStatusItem directly or orchetect/MenuBarExtraAccess for an animated status icon
- macOS has no AVAudioSession: AVAudioPlayer/NSSound mix over other audio without pausing music; use AudioServicesSetProperty(kAudioServicesPropertyIsUISound) to respect the 'Play user interface sound effects' system setting (NSSound ignores it)
- Mac App Store is infeasible: sandbox forbids consuming event taps and CGEvent paste injection (guideline 2.4.5 rejections); ship Developer ID + Hardened Runtime + notarytool + stapler + Sparkle 2 (EdDSA SUPublicEDKey, appcast, generate_appcast; Sparkle compares CFBundleVersion not marketing version; never codesign --deep)
- Wispr Flow (Electron) measured ~800MB RAM and ~8% CPU idle on an M1 Pro MacBook with fan-spin and app-freeze complaints on Reddit — the top cited reason users switch to native alternatives; native equivalents idle at ~0% CPU
- Electron cannot create non-activating panels (NSWindow assertion, issue #35815; panel PR #34388 was a runtime hack) and needs custom native modules for fn capture, AX insertion, and secure-input detection — eliminating its advantages for this app
- Best open-source references: Beingpax/VoiceInk (GPL-3.0, ~5.9k stars, whisper.cpp+KeyboardShortcuts+Sparkle, hybrid PTT), kitlangton/Hex (TCA+WhisperKit+FluidAudio Parakeet, HotKeyProcessor.swift, Sauce), cjpais/Handy (Tauri counter-example), 10xChengTu/input0 fn-key design doc, enigo-rs/enigo for CGEvent typing
- macOS Tahoe (26.x) tightened synthesized-event acceptance (CGXSenderCanSynthesizeEvents WindowServer gate); check CGPreflightPostEventAccess separately from AXIsProcessTrusted and test paste injection on Tahoe
- Karabiner-Elements is the most common third-party conflict for fn-key capture; Wispr Flow falls back to Ctrl+Opt when an external non-Apple keyboard prevents fn detection
- Wispr Flow ships URL schemes like wispr-flow://start-hands-free for automation integration (Raycast/Shortcuts)

## RECOMMENDATIONS
- Build native Swift (SwiftUI app shell + AppKit NSPanel HUD). Electron is disqualified by fn-key capture, non-activating overlays, AX insertion, and idle footprint; every workaround requires writing the same native code anyway.
- Hotkey stack: CGEventTap (.defaultTap, flagsChanged+keyDown mask) on a dedicated thread for fn/bare-modifier PTT with consume-on-match, plus sindresorhus/KeyboardShortcuts for user-customizable combo hotkeys. Implement tap health monitoring (re-enable on kCGEventTapDisabledByTimeout, 5s tapIsEnabled poll).
- Copy Hex's HotKeyProcessor semantics: 0.3s hold threshold for modifier-only keys → shorter press = toggle lock, longer = push-to-talk ending on keyUp; double-tap = hands-free lock; ESC cancels. Offer hybrid/PTT/toggle as a setting like VoiceInk.
- Onboarding must include an fn-key step that reads com.apple.HIToolbox AppleFnUsageType and deep-links to System Settings to set 'Press 🌐 key to' → 'Do Nothing', plus detection of Karabiner-Elements conflicts.
- Audio: AVAudioEngine tap at hardware format → AVAudioConverter to 16kHz mono; rebuild engine on AVAudioEngineConfigurationChange; keep engine prewarmed (or start on keyDown) to avoid missing first words; buffer from tap install to cover AirPods HFP switch; skip setVoiceProcessingEnabled initially and offer optional 'mute music while dictating' instead.
- Insertion: default to save-clipboard → write transcript with org.nspasteboard.TransientType/AutoGeneratedType → synthesize Cmd-V (Sauce for layout-correct keycode) → restore clipboard after delay; use AX (kAXSelectedTextAttribute) where a per-app capability probe succeeds; per-app overrides table; poll IsSecureEventInputEnabled and show a 'secure field' HUD state instead of failing silently.
- Permissions UX: single setup window with live-polling cards (Mic via AVCaptureDevice.requestAccess; Accessibility via AXIsProcessTrustedWithOptions prompt + x-apple.systempreferences deep link); treat Input Monitoring as implied by Accessibility; document tccutil reset for support; keep signing identity stable across builds so TCC grants persist.
- HUD: NSPanel(.nonactivatingPanel, borderless, clear, .screenSaver level, canJoinAllSpaces+fullScreenAuxiliary, ignoresMouseEvents) hosting SwiftUI via NSHostingView; bottom-center pill like Wispr; SwiftUI TimelineView+Canvas waveform first, CADisplayLink/Metal only if profiling demands; NSStatusItem (not MenuBarExtra) for an animated menu bar icon; LSUIElement accessory app.
